# QSNCC — ระบบบันทึกการซ่อมเครื่องฆ่าเชื้อ

แอพหน้างาน (mobile-first) สำหรับทีมช่างศูนย์การประชุมแห่งชาติสิริกิติ์ ใช้กรอกข้อมูล
การตรวจ/ซ่อม **เครื่องฆ่าเชื้อ 1,503 เครื่อง · 70 จุดติดตั้ง · 4 โซน** แทนการพิมพ์ตรง
ลงสเปรดชีต โดยยังอ่าน/เขียนข้อมูลไปที่ **Google Sheets ชุดเดิม** เพื่อให้ชีตรายงาน/
สรุปข้อมูลที่มีอยู่ใช้ต่อได้เหมือนเดิม

## สถาปัตยกรรม
```
 มือถือช่าง (index.html)  ──GET──►  Apps Script doGet   ──►  ชีต "ทะเบียนเครื่อง" + "ข้อมูลหลัก"
   • ทำงานออฟไลน์ได้                                            (ดึง master data ขับ UI เลือกเครื่อง)
   • เก็บ outbox ใน localStorage ──POST(batch)──► doPost ──►  ชีต "บันทึกการซ่อม"
   • sync เมื่อมีสัญญาณ                                          (เขียนแถวใหม่ครบทุกฟิลด์)
```
- **Frontend:** `index.html` ไฟล์เดียว (HTML+CSS+JS inline) — mobile-first, offline-first
- **Backend:** `Code.gs` (Google Apps Script) ผูกกับไฟล์ Google Sheets เดิม
- **Manifest:** `appsscript.json` (timezone Asia/Bangkok, V8, deploy เป็น Web App)
- **`master-data.json`:** ชุดข้อมูลตั้งต้นที่สกัดจากไฟล์ Excel — ฝังอยู่ใน `index.html`
  แล้ว ทำให้แอพใช้งานได้ทันทีแบบออฟไลน์ ก่อนเชื่อมต่อ backend

## ไฟล์ในโปรเจกต์
| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | แอพหน้างาน (เปิดในเบราว์เซอร์มือถือ / โฮสต์เป็นไฟล์เดียว) |
| `Code.gs` | Backend Apps Script — `doGet` (master + history), `doPost` (batch save) |
| `appsscript.json` | Manifest สำหรับ deploy เป็น Web App |
| `master-data.json` | ทะเบียนเครื่อง + master ที่สกัดจาก Excel (อ้างอิง/ฝังในแอพ) |

## วิธีติดตั้ง (Deploy)

### 1) ฝั่ง Google Sheets + Apps Script
1. เปิดไฟล์ Google Sheets เดิม (ที่มีชีต `ทะเบียนเครื่อง`, `บันทึกการซ่อม`, `ข้อมูลหลัก`, `รายงาน`, `สรุปข้อมูล`)
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. วางเนื้อหา `Code.gs` ลงในไฟล์ `Code.gs` ของโปรเจกต์ (ถ้ามีโค้ดเดิมให้แทนที่)
4. (ถ้าต้องการ) ตั้งค่า manifest ตาม `appsscript.json`
5. กด **Deploy → New deployment → เลือกชนิด Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (หรือ *Anyone with Google account* ตามนโยบายองค์กร)
6. คัดลอก **Web app URL** (ลงท้าย `/exec`)

> Apps Script จะทำงานบนไฟล์ที่มันผูกอยู่ (`getActiveSpreadsheet()`) — ไม่ต้องใส่ Spreadsheet ID

### 2) ฝั่งแอพมือถือ
- เปิด `index.html` (โฮสต์บน GitHub Pages / Google Sites / ไฟล์ในเครื่อง ก็ได้)
- ไปที่ **⚙️ ตั้งค่าการเชื่อมต่อ** → วาง Web app URL → **บันทึก & ทดสอบ**
- แอพจะดึงทะเบียนเครื่องล่าสุดมาแคชไว้ และพร้อมส่งข้อมูลขึ้นชีต

## Flow การใช้งานหน้างาน
1. **เริ่มรอบ** — เลือกวันที่ + รอบ (R1/R2) + ชื่อผู้บันทึก (จำไว้ทั้ง session)
2. **เลือกจุดติดตั้ง** — ค้นหาจาก 70 จุด (แสดงโซน + ตำแหน่งช่วยจำ เช่น "Locker NCC")
3. **เลือกเครื่อง** — เครื่องในจุดนั้นแสดงเป็นปุ่ม จัดกลุ่มตามประเภท (นั่ง/ยืน/หญิง/พิการ)
   แตะเลือกได้หลายเครื่องพร้อมกัน · เครื่องที่เคยบันทึกวันนี้มีป้าย "วันนี้"
4. **กรอกรายละเอียดต่อเครื่อง** — เลือก *อาการที่พบ* (chip 6 อาการ), *อาการที่ซ่อมเสร็จ*
   (เลือกได้เฉพาะอาการที่พบ) + ปุ่มลัด **"ซ่อมครบ"**, ระบบ *auto-suggest สถานะ*
   จากอาการที่ค้าง (แก้เองได้), ใส่รายละเอียด/หมายเหตุ
5. **บันทึกทั้งหมด** — ส่งเป็น batch เดียวขึ้น Google Sheets (ลดจำนวนครั้งเรียก API)
6. ไปจุดถัดไป ทำซ้ำจนครบรอบ

### รองรับเคสซ่อมบางส่วน
เครื่อง `R-B101-F6` พบ 2 อาการ (ฝาหน้า/ฝาหลัง + น้ำยารั่ว) รอบนี้ซ่อมได้แค่น้ำยารั่ว →
บันทึก 1 รายการ: พบ = 2, ซ่อมเสร็จ = น้ำยารั่ว, ระบบคำนวณ *ค้าง = ฝาหน้า/ฝาหลัง*,
สถานะ = **เสร็จบางส่วน** (auto) รอบถัดไปที่ซ่อมเสร็จก็บันทึกเป็นรายการใหม่ (วันที่ใหม่)
— ดูประวัติต่อเนื่องได้จากเมนู **ประวัติเครื่อง** ด้วย Machine ID เดียวกัน

## ฟีเจอร์
- 📱 **Mobile-first** ปุ่มใหญ่ กดง่ายด้วยนิ้วหน้างาน
- 📴 **ออฟไลน์** — บันทึกลง localStorage ก่อน แล้ว sync อัตโนมัติเมื่อมีสัญญาณ
  (จุดสัญญาณจุด: มีแบนเนอร์ "รอ sync" ชัดเจน + ไฟสถานะเครือข่ายบนหัว)
- 🔍 **ค้นหาเร็ว** — พิมพ์กรองรายชื่อจุด/เครื่อง
- 📊 **สรุปความคืบหน้ารอบปัจจุบัน** — กี่จุด/กี่เครื่องที่บันทึกแล้ว/กี่รายการรอส่ง
- ⚠️ **กันบันทึกซ้ำ** — เครื่องเดิม + วันเดิม เตือนก่อนบันทึกซ้ำ
- 🕘 **ประวัติย้อนหลังต่อเครื่อง** — ดึงจากชีตบันทึกการซ่อม + รายการในเครื่อง

## โครงสร้างข้อมูล (อ้างอิงไฟล์จริง)
- **โซน (4):** T=Thaibev, R=Ratchada, L=Lake Side, Y=Yasub
- **ประเภทสุขภัณฑ์ (4):** S=ชายนั่ง, U=ชายยืน, F=หญิง, D=คนพิการ *(master-driven ไม่ hardcode)*
- **Machine ID:** `[รหัสจุด]-[ประเภท][เลขเครื่อง]` เช่น `R-B101-F6` (ไม่ซ้ำทั้ง 1,503 เครื่อง)
- **รหัสจุดที่ไม่เป็นแพทเทิร์นมาตรฐาน** (เช่น `R-VIPRoom1(1)`, `L-LM05-2`) รองรับเป็น string ตรง ๆ
- **อาการเสีย (master):** หัววงจรเสีย, รางแบตเตอรี่ชำรุด, ฝาหน้า/ฝาหลัง, น้ำยารั่ว, ตัวเครื่อง, ท่อหลุด
  *(เพิ่มได้ในชีต "ข้อมูลหลัก" โดยไม่ต้องแก้โค้ด — backend อ่านจาก master แบบ header-driven)*
- **สถานะซ่อม:** เสร็จสิ้น, เสร็จบางส่วน, รออะไหล่, ส่งซ่อมภายนอก, ยกเลิก

### ฟิลด์ที่เขียนลงชีต "บันทึกการซ่อม" (1 รายการ/แถว)
เขียนแบบ **header-driven** — จับคอลัมน์จากชื่อหัวคอลัมน์ จึงทนต่อการสลับคอลัมน์:
วันที่, รอบ, Machine ID, รหัสจุด, เลขเครื่อง, ประเภทที่ใช้, โซน, ชื่อโซน, รหัสอาการ,
คอลัมน์ติ๊ก ✓ แยกตามอาการ (หัววงจรเสีย/รางแบตเตอรี่ฯ...), อาการเสีย, สรุปอาการ (รหัส+ชื่อ),
รายละเอียด, สถานะ, ผู้บันทึก, หมายเหตุ, เดือน/ไตรมาส/ปี/คีย์ช่วงเวลา, cS/cU/cF/cD, ลำดับ(auto)

> **หมายเหตุ schema:** ข้อมูล *อาการที่ซ่อมเสร็จ* และ *อาการที่ยังค้าง* ไม่มีคอลัมน์รองรับ
> ในสเปรดชีตเดิม — `Code.gs` จึง **เพิ่ม 2 คอลัมน์ท้ายชีต** (`อาการที่ซ่อมเสร็จ (รหัส+ชื่อ)`,
> `อาการที่ยังค้าง (รหัส+ชื่อ)`) อัตโนมัติครั้งแรกที่บันทึก โดย**ไม่กระทบสูตรของชีตรายงาน/
> สรุปข้อมูลเดิม** ที่อ้างอิงคอลัมน์เดิม

## ขอบเขต (ตามที่ตกลง — ยังไม่ทำในเวอร์ชันนี้)
- ไม่มีระบบ auth ซับซ้อน (พิมพ์/เลือกชื่อผู้บันทึกพอ)
- ไม่มี push notification (ต่อ LINE ภายหลังได้)
- ไม่ย้ายหน้ารายงาน/สรุปเข้าแอพ — ยังดูจาก Google Sheets เหมือนเดิม
